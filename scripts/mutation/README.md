# Мутационная проверка тестов

Вносит в код заранее описанные ошибки («мутации») и проверяет, что тесты их ловят.
Зелёные тесты доказывают, что код их проходит; убитые мутации — что тесты способны
заметить регрессию.

```sh
npm run test:mutation                  # все наборы
npm run test:mutation -- shared-query  # выбранные наборы
npm run test:mutation -- --markdown    # плюс таблицы для журнала и README
```

## Как работает

Для каждого набора (`src/suites/*.ts`):

1. Базовый прогон тестов набора — должен быть зелёным, иначе мутации не запускаются.
2. Для каждой мутации: фрагмент `from` должен встречаться в файле ровно один раз;
   он заменяется на `to`, запускается `vitest run` с JSON-репортером, файл
   восстанавливается.
3. После набора файл сверяется с исходным.

| Статус     | Значение                                                                                |
| ---------- | --------------------------------------------------------------------------------------- |
| `killed`   | хотя бы один тест упал — регрессия ловится                                              |
| `survived` | все тесты зелёные — дыра в тестах                                                       |
| `invalid`  | фрагмент не найден или найден больше одного раза — код изменился, мутацию надо обновить |
| `timeout`  | прогон завис и снят по таймауту (вместе с воркерами vitest)                             |
| `error`    | vitest завершился с ошибкой без упавших тестов (например, мутант не парсится)           |

Код выхода 0 — только если все мутации `killed`.

## Как добавить мутацию

Мутация — правдоподобная регрессия конкретного требования, а не случайная правка:

```ts
{
  name: 'data всегда заменяется (isEqual игнорируется)',
  from: 'data: unchanged ? state.data : data,',
  to: 'data,',
}
```

- `survived` — дописать тест, а не удалять мутацию.
- `invalid` после рефакторинга — обновить `from`/`to` под новый код, сохранив смысл.

## Безопасность

Мутант пишется прямо в исходный файл. Рядом создаётся `<файл>.mutation-backup`
(в `.gitignore`); при Ctrl+C и штатном завершении файл восстанавливается, а копия
удаляется. Если копия осталась (процесс убит `kill -9`), раннер откажется запускаться,
пока файл не восстановлен вручную. Во время прогона не редактируйте целевые файлы;
открытый dev-сервер Vite будет показывать мутанта через HMR.
