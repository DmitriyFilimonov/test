# Требования к шагу 02 — таблица

Выявлены при завершении шага 01 (2026-09-15, `docs/ai-log/2026-09-15-step-01-tree-render.md`).

- [ ] **Состояние раскрытия не попадает в Redux ни при каких условиях.** Сейчас это
      `Set<string>` в `useReducer` внутри `OrgTreeView` (`@entities/org-tree`). Если таблице понадобится
      связь с деревом (общее раскрытие, выделение), состояние поднимается в общего
      родителя или в React-контекст, но не в стор. В Redux — только серверные данные.
- [ ] **Агрегаты по поддереву уже есть и уже показываются в дереве:** `selectSubtreeAggregates`
      и `aggregateSubtrees` из `@entities/org-tree`, поле `subtree` у узлов видимого дерева.
      `headcount` в API — собственные сотрудники; общая численность = собственные + общая у
      дочерних; общая эффективность взвешена по собственным сотрудникам каждого узла (каждый
      человек один раз); нет людей — `null`. Таблица должна использовать те же понятия и
      подписи, что карточка дерева: «Собственных сотрудников» / «Общая численность»,
      «Собственная эффективность» / «Общая эффективность», у листьев — «Численность» /
      «Эффективность» (`getNodeMetrics`, `getMetricRows` в `@entities/org-tree` — таблица берёт
      их оттуда, не копирует).
- [ ] **Сортировка детей** — простое сравнение строк (не `Intl.Collator`, см. журнал):
      «ё» встаёт после «я». Если таблица сортирует по имени, выбрать тот же порядок или
      осознанно отличный и описать.
