# Требования к шагу 02 — таблица

Выявлены при завершении шага 01 (2026-09-15, `docs/ai-log/2026-09-15-step-01-tree-render.md`).

- [x] **Состояние раскрытия не попадает в Redux ни при каких условиях.** Сейчас это
      `Set<string>` в `useReducer` внутри `OrgTreeView` (`@entities/org-tree`). Если таблице понадобится
      связь с деревом (общее раскрытие, выделение), состояние поднимается в общего
      родителя или в React-контекст, но не в стор. В Redux — только серверные данные.
      Часть 3 (`2026-09-15-step-02-url-views.md`): `useExpansion` — `useReducer` на странице,
      `OrgTreeView` управляемый; в стор раскрытие и выделение не попадают.
- [x] **Агрегаты по поддереву уже есть и уже показываются в дереве:** `selectSubtreeAggregates`
      и `aggregateSubtrees` из `@entities/org-tree`, поле `subtree` у узлов видимого дерева.
      `headcount` в API — собственные сотрудники; общая численность = собственные + общая у
      дочерних; общая эффективность взвешена по собственным сотрудникам каждого узла (каждый
      человек один раз); нет людей — `null`. Таблица должна использовать те же понятия и
      подписи, что карточка дерева: «Собственных сотрудников» / «Общая численность»,
      «Собственная эффективность» / «Общая эффективность», у листьев — «Численность» /
      «Эффективность» (`getNodeMetrics`, `getMetricRows` в `@entities/org-tree` — таблица берёт
      их оттуда, не копирует).
      Часть 1 (`2026-09-15-step-02-table-model.md`): итоги строк — проекция
      `selectSubtreeAggregates`, `formatPerformance` округляет как карточка (закреплено тестом).
      Часть 2 (`2026-09-15-step-02-table-ui.md`): понятия те же, подписи колонок — из ТЗ части 2
      («Всего сотрудников», «Бюджет суммарный», «Средняя эффективность») и отличаются от
      карточки; `getMetricRows` таблица не использует — у неё по одной колонке на показатель и
      только итоги.
- [x] **Сортировка детей** — простое сравнение строк (не `Intl.Collator`, см. журнал):
      «ё» встаёт после «я». Если таблица сортирует по имени, выбрать тот же порядок или
      осознанно отличный и описать.
      Уточнено в части 0 шага 02 (`2026-09-15-step-02-multikey-cache.md`): таблица не сортирует сама —
      порядок задаёт сервер (`order`), `name` у сервера по локали ru. Порядки дерева и
      таблицы расходятся не только на «ё»: латиница по кодам раньше кириллицы, у коллатора
      ru — позже; на данных мока — 4 группы братьев из 20. Решить, выравнивать ли дерево.
      С группировкой строк таблицы (`2026-09-15-step-02-grouped-table.md`) при сортировке по
      имени обе панели показывают одну иерархию, и расхождение видно в split строка к строке.
      Решено оставить порядки разными: дерево не трогать, совпадение порядков в ТЗ не требуется
      (решение автора). → `2026-09-15-step-02-grouped-table.md`
- [x] **Таблица упорядочивается по `order` из ответа и не пересортировывает сама.** Данные
      приходят со всеми узлами; `matches` — совпадение с `q` только по собственному имени.
      → `selectTableRows`, `2026-09-15-step-02-table-model.md`
      Пересмотрено (`2026-09-15-step-02-grouped-table.md`): строки сгруппированы по иерархии,
      `order` задаёт порядок соседей внутри родителя; клиент по-прежнему не сравнивает строки.
- [x] **Фильтр задаёт `debounceMs: 250` в `createQuery` оргдерева.** Сейчас не задан (0):
      без фильтра он только откладывал бы первую загрузку дерева. Эффект `debounce` в
      redux-saga только trailing — с 250 мс первый запрос тоже уйдёт через 250 мс после
      подписки; оценить на первой загрузке или сделать первый запуск без окна.
      Решено иначе в части 2 (`2026-09-15-step-02-table-ui.md`): по ТЗ дебаунс 250 мс — в `useTableModel`, на
      переносе текста поля в `params`; `debounceMs` у запроса не задан (иначе окно легло бы и на
      первую загрузку, и на ввод второй раз).
- [x] **`isPlaceholder`** — при смене параметров таблица показывает данные прежнего ключа
      (`useOrgTree(params).isPlaceholder`); решить, как это обозначить визуально.
      → строки приглушены статическим правилом по `data-placeholder`, `aria-busy`, индикатор
      «Обновление…»; `2026-09-15-step-02-table-ui.md`
- [x] **UI таблицы строится на модели части 1** (`2026-09-15-step-02-table-model.md`): строки —
      `selectTableRows(state, params)`, ячейки — `formatBudget` / `formatPerformance`. Новых
      обходов и расчёта итогов в UI нет: не хватает поля в строке — расширяется проекция в
      `model/table.ts`. `TableRow` содержит только итоги; собственные значения, если они нужны
      в таблице, добавляются в проекцию из полей узла (`headcount`, `performance`).
      → `useTableModel`, `OrgTable`; `2026-09-15-step-02-table-ui.md`
- [x] **Приглушение несовпавших узлов дерева** — по `data.matches` у узлов `selectVisibleTree`
      (часть 1 добавила только флаг). При пустом `q` флаг true у всех.
      → `data-dimmed` и статическое правило, только в режимах split и table;
      `2026-09-15-step-02-url-views.md`
- [x] **Строки таблицы при `isPlaceholder`** — это строки прежнего ключа: его `matches` и
      `order`, то есть прежний фильтр и прежняя сортировка, пока не пришёл ответ по новым
      параметрам. → тест `useTableModel` на реальном сторе; `2026-09-15-step-02-table-ui.md`
- [x] **Параметры таблицы из URL (часть 3).** `useTableModel` параметры не хранит:
      `params` и `onParamsChange` подключаются к адресу. Внешнее изменение `q` («назад»)
      переносится в поле; своё значение, применённое с опозданием (навигация в transition), поле
      не затирает. Проверить в браузере на реальном роутере: назад/вперёд во время паузы ввода.
      → `useOrgDashboardParams`, `2026-09-15-step-02-url-views.md`. В браузере проверено «назад»
      после серии правок фильтра; назад/вперёд именно во время паузы ввода — не проверялось.
- [ ] **Layout shift при смене сортировки с медленным ответом — решение за автором.** Строки
      с ключом по `id` в `React.memo` не перерисовываются при смене порядка (критерий
      профайлера), но React переставляет в DOM только часть строк; оставшиеся на месте Chrome
      считает сдвинувшимися. Ответ быстрее 500 мс после клика — сдвиги с `hadRecentInput`, CLS 0;
      медленнее — CLS 0.03–0.1 за смену (замер `2026-09-15-step-02-table-ui.md`). Снимается ключами строк по
      позиции (CLS 0 при любой задержке, но при смене порядка перерисовываются строки, на чьих
      позициях оказались другие подразделения) — это противоречит критерию профайлера.
- [ ] **Сортировка во время паузы ввода — два запроса.** `toggleSort` не забирает черновик
      фильтра: уходят сортировка со старым `q`, затем через остаток паузы — новый `q`. Если
      мешает — `toggleSort` применяет и черновик, отложенная отправка снимается.
