# Требования к применению патчей потока (часть 3 шага 03)

Выявлены при реализации частей 1 и 2 шага 03 (2026-09-16). Часть 1 довела поток до состояния
соединения и `lastSeq`, часть 2 — до инкрементального пересчёта агрегатов. Применение патчей
к данным ни там, ни там не делалось, но решения уже приняты — здесь они лежат для агента
следующей части.

- [x] **Индекс агрегатов живёт в сторе рядом с данными, патч применяется в редьюсере.**
      `aggregateSubtrees` — на ответ GET, `applyAggregatePatch` — на событие `patch`, селектор
      только читает готовый индекс. Селектор для этого не годится: `createSelector` видит лишь
      текущие данные, а инкрементальный пересчёт зависит от предыдущего индекса; хранить
      «предыдущее» внутри селектора — скрытое изменяемое состояние, которое ломается на
      многоключевом кеше `@shared/query` (у каждого ключа параметров свои данные) и на втором
      сторе в тестах. Обоснование целиком — `docs/ai-log/2026-09-15-step-03-incremental-aggregates.md`.
      → Выполнено иначе: цель (полный расчёт на GET, `applyAggregatePatch` на патч, селектор
      читает готовый индекс) достигнута, но индекс лежит не в сторе, а в кеше по ссылке на массив
      данных; патч применяется экшеном `patched` из `@shared/query`. Почему —
      `2026-09-16-step-03-live-apply.md`.
- [x] **Сигнатура `applyAggregatePatch(index, previousNodes, currentNodes, changes)`.** Разностный
      пересчёт требует прежних значений узла; редьюсер их знает, потому что патч применяется
      к массиву из стора. → `2026-09-16-step-03-live-apply.md`
- [ ] **Бюджет в схеме не целый.** `budget: z.number().min(0)` без `.int()`, хотя разностный
      пересчёт бюджета точен только на целых. Мок-API отдаёт целые (кратные 10 000), поэтому
      сейчас дрейфа нет. Решить: ужесточить схему до `.int()` (изменение контракта) либо
      пересчитывать бюджет затронутых поддеревьев полностью.
      Не решено в части 3: это изменение контракта, решение за автором. Поток мока бюджеты не
      меняет, добавленные узлы приходят с целым бюджетом (`2026-09-16-step-03-live-apply.md`).
- [x] **Разрыв `seq`.** `seq` монотонен от старта сервера и нужен ровно для обнаружения
      пропуска: если `seq` пришедшего патча не следующий за `lastSeq`, инкрементально
      применять нельзя — нужен полный перезапрос `GET /api/org-tree`.
      → `requested({ force })` текущего ключа; так же — `hello` после переподключения с другим
      номером. `2026-09-16-step-03-live-apply.md`
- [ ] **Перенос поддерева.** Смены `parentId` в контракте патча нет (`nodes` меняют только
      метрики, структуру меняют `added`/`removed`). Если она появится, вести её по ветке
      полного пересчёта, как добавление и удаление: `applyAggregatePatch` берёт цепочку
      предков из текущих данных и разностным путём перенос не отработает.
      В части 3 контракт не менялся — пункт остаётся на будущее.
