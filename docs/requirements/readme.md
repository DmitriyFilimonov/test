# План README

Что переносить из `docs/ai-log/` в README при сведении. Черновик — `README.md` (2026-09-15);
пункты отмечаются `[x]` при финальном сведении, после подтверждения автора. Остальное остаётся в `docs/`
как доказательная база; из README на неё ссылаться.

- [ ] **Качество тестов: мутационное тестирование** — три абзаца прозы и таблица
      «что сломали → что упало». Таблицу генерировать `npm run test:mutation -- --markdown`
      в момент сведения; указать команду, чтобы читатель мог воспроизвести. Контекст —
      `2026-09-15-step-01-shared-query.md`, `2026-09-15-step-01-review-fixes.md`,
      `2026-09-15-step-01-mutation-runner.md`.
- [ ] **Рефкаунт подписок** — абзац: счётчик и задача в вотчере, последовательный
      `take`, не больше одного запроса в полёте, отмена при переходе в 0.
- [ ] **Сохранение ссылки на `data` при равных данных** — абзац; указать реально
      реализованный `isEqual` оргдерева (см. `step-02-entities.md`), а не «по `updatedAt`».
- [ ] **Отмена и `catch`** — почему проверка `cancelled()` в `catch` лишняя
      (`iterator.return()` минует `catch`) и почему внешний `AbortError` обрабатывается
      как отмена, а не простым `return` (иначе статус залипает в `loading`).
- [ ] **Известное ограничение: отмена без отложенного окна.** Отменённый запрос при
      быстром монтировании/размонтировании — реальный сценарий быстрой навигации
      (StrictMode в приложении выключен, двойных эффектов в dev нет); обрабатывается корректно (abort, без ошибки).
      Зрелые библиотеки откладывают отмену на короткое окно, чтобы не гонять сеть при
      перескоках; здесь это сознательно не сделано. Способ снятия — отложить `cancel`
      на N мс после перехода счётчика в 0 и отменять отмену при новой подписке.
- [ ] **Раздел про AI: «сгенерировано / переписано руками».** Собрать из секций
      «Авторство» записей журнала, не по памяти.
- [ ] **Раскладка tidy tree** — Walker в линейной версии Buchheim–Jünger–Leipert; инварианты
      проверяются программно (300 случайных деревьев, зеркало, изоморфизм); линейность —
      замер 1k/10k/100k. Эксперимент: однопроходный алгоритм зеркально симметричен на
      53 000 деревьях, усреднение не понадобилось. → `2026-09-15-step-01-tree-render.md`
- [ ] **Критический путь рендеринга** — размеры узлов из темы, стили по data-атрибутам,
      панорама/зум императивно в rAF с коммитом в конце жеста, React.memo (раскрытие
      узла перерисовывает 4 OrgNode из 22). Таблица сравнения панорамы: transform на
      `<g>` / viewBox / CSS transform (эталон, запрещён «без inline-CSS»). → `2026-09-15-step-01-tree-render.md`
- [ ] **Трактовки** — «второй уровень открыт» = раскрыты корни (видны дивизионы и
      отделы); «абсолютные импорты» = импорты по имени пакета без paths; клавиатурная
      навигация исключена пользователем; лес с любым числом корней раскладывается через виртуальный
      корень. → `2026-09-15-step-01-tree-render.md`
