# Шаг 03, часть 3 — Патчи потока в кеше и подсветка обновлений

Дата: 2026-09-16

Патчи потока применяются к записи текущего ключа кеша без запроса, записи других ключей протухают,
пропуск `seq` вызывает перезапрос. Итоги пересчитываются инкрементально, изменённые ячейки таблицы
и поля карточек подсвечиваются CSS-анимацией, которая гаснет за 1.5 с.

## Решения

**Текущий ключ — последний, на который подписался UI.** Сага запоминает `params` из
`orgTreeQuery.actions.subscribed`: `patched` и `requested` принимают параметры, а не ключ.
Отброшено: `lastKey` кеша — это ключ последнего _успешного_ ответа, при смене фильтра он указывает
на заглушку, которую ответ нового ключа всё равно заменит; хранить `params` в записи кеша — менять
форму `QueryState` ради одного потребителя. Патч к ключу без своих данных (первый запрос в полёте,
на экране заглушка) не применяется: данные придут ответом.

**Остальные ключи протухают, а не патчатся.** Их `matches` и `order` посчитаны сервером под свои
`q`, `sort` и `dir`. Пропатчить значения без пересчёта порядка — показать неверную сортировку при
возврате к ключу. Пересчитать порядок — продублировать серверную сортировку, от которой ушли в шаге 02. `invalidated` сбрасывает `fetchedAt`, данные остаются: при возврате виден прежний ответ, пока
идёт перезапрос; без возврата запись вытеснит `gcTime`. Предикат принимает ключ: редьюсер знает
только ключи.

**Индекс итогов — в кеше по ссылке на массив данных, а не в сторе.** Это пересмотр решения части 2
(`2026-09-15-step-03-incremental-aggregates.md`: «индекс в сторе, патч в редьюсере»). Часть 3 провела
патч через общий `patched` из `@shared/query`, который про итоги ничего не знает. Слайс «ключ →
индекс» дублировал бы жизненный цикл записи кеша: вытеснение по `gcTime`, заглушку прежнего ключа,
сохранение ссылки при равных данных. Получились бы два источника правды об одном ключе.
`WeakMap<массив данных, индекс>` живёт ровно столько, сколько данные, общий для всех ключей и сторов,
и остаётся кешем чистой функции: значение для массива всегда равно `aggregateSubtrees(nodes)`.
Сага считает новый массив и его индекс (`applyAggregatePatch` от индекса прежних данных) и кладёт
индекс в кеш _до_ `put`: подписчики стора вызываются синхронно внутри `put`, и селектор находит
готовый индекс. Существующий тест «один вызов расчёта на данные» не менялся. Новый тест считает
вызовы `aggregateSubtrees`: на патч их ноль.

**`updater` — функция, возвращающая заранее посчитанный массив.** Индекс для ссылки нужен до
диспатча, а ссылку на результат `updater`, вызванного в редьюсере, сага не получит. `select` и
`put` выполняются одним синхронным шагом саги, данные записи между ними не меняются.

**Пропуск `seq`.** Ожидается `lastSeq + 1`. Номер больше — пропущенные патчи потеряны: патч с
пропуском не применяется, текущий ключ перезапрашивается `requested({ force })`, остальные
протухают. `hello` после переподключения с номером, отличным от последнего учтённого, — тоже
пропуск: пока соединения не было, сервер ушёл вперёд или перезапустился. Повтор учтённого номера
игнорируется.

**Применение патча идемпотентно.** Ответ на перезапрос может прийти раньше события, которое в нём
уже учтено. Метрики в патче — значения, а не приращения, их повтор безвреден. Удаление
отсутствующего узла пропускается. Добавление узла с существующим id пропускается, иначе id
задвоился бы.

**Номера обновлений в сторе, состояния «подсвечено» нет.** `orgTreeUpdates`: id узла → номер патча,
последним изменившего каждое показанное значение (`ownHeadcount`, `ownPerformance`,
`totalHeadcount`, `totalBudget`, `totalPerformance`). Номер только растёт, таймеров нет, гаснет
CSS. Записи удалённых узлов удаляются. Номера приходят отдельным экшеном после `patched` в том же
шаге саги: React объединяет оба обновления в один рендер (DOM-тест: ровно 3 рендера строк). В
`selectTableRows` номера не входят, чтобы второй экшен не пересчитывал строки: таблица и дерево
берут номер по id при отрисовке и передают строке и карточке примитивами — `memo` работает как
раньше. Отброшено: сравнение с прежними значениями в компоненте (скрытое состояние на каждую
ячейку); атрибут только у ячеек последнего патча (при быстром потоке анимации обрывались бы).

**Подсвечивается видимое изменение.** Значения до и после сравниваются в том виде, в каком их
показывают таблица и карточка (`getNodeMetrics`, эффективность округлена), и только вдоль цепочек
изменённых узлов и родителей добавленных и удалённых. Не подсвечиваются 68.6 → 69.3 (обе «69») и
итог, который не изменился: эффективность листа при смене его численности. Для этого
`getNodeMetrics` стал обобщённым по аргументу: он читает только `node` и `subtree`, а
`format.test.ts` передаёт литерал полного `OrgTreeItem` — с узким типом его отверг бы контроль
лишних свойств.

**Перезапуск анимации — `key` с номером патча.** Правило одно, статическое:
`&[data-updated] { animation: fade 1.5s ease-out }`, keyframes — только `from` с цветом обновления
через CSS-переменную, конец — собственный фон элемента. Смена значения `data-updated` анимацию не
перезапускает: имя анимации то же. Поэтому ячейка и значение карточки получают `key` с номером
патча, и повторное обновление до угасания даёт новый DOM-элемент с анимацией с начала.
Перемонтируется только сам `<td>` или `<dd>`: строка, таблица и карточка остаются (DOM-тест
сравнивает элементы). Отброшено: два одинаковых `@keyframes` с разными именами, выбираемых по
чётности номера. Номер патча общий на всё дерево, и у ячейки, изменённой в патчах 4 и 6, чётность
не меняется, так что анимация не перезапустилась бы. Понадобился бы свой счётчик на каждую ячейку.

**Подсвечиваются только обновления после монтирования.** `useFreshUpdates` один раз запоминает
номера при монтировании (`useState`). Без этого строка или карточка, появившаяся при раскрытии,
фильтре или смене вида, мигала бы давними обновлениями.

**`prefers-reduced-motion`.** Под `@media (prefers-reduced-motion: reduce)` —
`animation-timing-function: step-end`: фон обновления стоит те же 1.5 с и снимается скачком, без
перехода. Совсем подсветка не убирается.

**Структура не пересобирается при патче метрик.** `selectChildrenIndex` и `selectParentIndex`
теперь строятся от `selectStructure`: мемоизация с `resultEqualityCheck` возвращает прежний
массив, если id, parentId и name на тех же местах. Без этого каждый патч создавал новые индексы,
`useOrgTreeStructure` — новый объект, и перерисовывалась вся страница с раскрытием. В индексе
детей могут остаться узлы прежних данных, поэтому `selectVisibleTree` берёт актуальный узел по id
(`selectNodeById`). Это оговорено в типе `ChildrenIndex`. Отброшено: индекс детей из одних id —
меняет `ChildrenIndex` в раскрытии, селекторах и их тестах.

**Добавленный узел** встаёт последним по `order` (сохраняется перестановка 0..n-1), его `matches` —
`q === ''`: совпадение с `q` клиент не вычисляет. **Удалённый** уходит, `order` следующих сдвигается.
Поддерево вместе с узлом не удаляется: мок удаляет только листья, удаление узла с детьми по
контракту — нарушение.

**Функции в экшенах.** API из ТЗ кладёт `updater` и `predicate` в payload. Это команды редьюсеру, а
не данные. Пути для `serializableCheck.ignoredActionPaths` экспортирует `@shared/query`, чтобы
стор не держал строки-пути у себя.

## Отступления от инструкции

- Решение части 2 «индекс в сторе, патч в редьюсере» пересмотрено: индекс — в кеше по ссылке на
  данные (см. «Решения»). В старую запись добавлена строка «Пересмотрено».
- ТЗ называет пропуском «пришёл `seq`, больший ожидаемого». Перезапрос делается ещё в одном
  случае: `hello` после переподключения с номером _меньше_ последнего учтённого (сервер
  перезапустился и вернул данные к сиду). Номер больше учтённого — буквально пропуск.
- «Вручную» проверено скриптом через Chrome DevTools Protocol (headless Chrome, свои порты 3101 и
  5273), а не руками. React DevTools Profiler в headless недоступен: пункт «патч листа
  перерисовывает строку, карточку и предков» проверен DOM-тестом со счётчиками рендеров, в
  Profiler — нет.
- Существующие тесты правились без изменения смысла: в стор трёх DOM-тестов добавлен слайс
  `orgTreeUpdates` (и сага патчей — в тесте страницы, как в `@app/web`), в `makeModel` теста
  `OrgTable` — поле `updates: {}`. В тест селекторов добавлен новый тест.

## Известные проблемы

- Ответ `GET /api/org-tree` не несёт `seq`. Патчи между ответом и первым `hello` пропуском не
  считаются. Ответ, собранный сервером раньше патча и пришедший позже, перезаписывает значения
  патча до следующего. Снимается номером в ответе GET.
- Бюджет в схеме не объявлен целым (`docs/requirements/step-03-live-apply.md`): решение за автором.
  Поток мока бюджеты не меняет.
- Перенос поддерева в контракте патча по-прежнему отсутствует.
