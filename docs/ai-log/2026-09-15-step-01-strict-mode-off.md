# Шаг 01 — приложение без StrictMode

Дата: 2026-09-15

В dev мок-сервер логировал два запроса `GET /api/org-tree` на первый рендер дерева.
Причина — `<StrictMode>` в `apps/web/src/main.tsx`: React в dev монтирует эффекты дважды,
`useQuerySubscription` отправлял «подписка → отписка → подписка», `@shared/query` запускал
запрос, отменял его при переходе счётчика в 0 и запускал второй. По решению пользователя
StrictMode выключен.

## Изменения

- `apps/web/src/main.tsx` — `<App />` рендерится без `<StrictMode>`, по-прежнему в
  `startTransition`.
- `apps/web/src/app/store/store.ts` — комментарий к `getStore` больше не ссылается на
  StrictMode.
- `packages/shared/query/src/createQuery.test.ts` — тест «StrictMode (подписка, отписка,
  подписка в одном тике)…» переименован в «быстрое размонтирование и монтирование (…)»;
  проверки те же.
  > Пересмотрено: `2026-09-15-step-02-multikey-cache.md` — по ТЗ шага 02 тест снова называется «16. StrictMode-последовательность (…)», проверяет один ключ.
- `README.md` — название теста в таблице мутаций, решение в разделе «Работа с AI»;
  `docs/requirements/readme.md`, `step-03-ui.md` — формулировки без StrictMode.
- Строки «Пересмотрено» в `2026-09-15-step-01-shared-query.md` и
  `2026-09-15-step-01-tree-render.md`.

## Решения

- **StrictMode выключен (решение пользователя).** Агент до правки объяснил причину и измерил
  сеть; пользователь счёл режим бесполезным для проекта. Что теряется: dev-проверка
  нечистых рендеров и эффектов без очистки (двойной вызов), предупреждения об устаревших API.
- **`@shared/query` не менялся.** Отмена при переходе счётчика в 0 нужна и без StrictMode —
  при быстром уходе со страницы и возврате; тест остался, сменилось только название.
  Отложенная отмена по-прежнему не сделана (известное ограничение в README).

## Известные проблемы

- Порядок `304`/`200` в логе у пользователя (`304`, затем `200`) обратный замеренному (`200`,
  затем `304`). Лог пишется по завершении ответа, а состояние HTTP-кеша у пользователя было
  другим; точная последовательность не воспроизводилась — после правки вопрос неактуален.
