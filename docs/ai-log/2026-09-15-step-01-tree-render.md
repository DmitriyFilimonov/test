## Решения

### Раскладка (@shared/tidy-tree)

- **Алгоритм — Walker в линейной версии Buchheim–Jünger–Leipert (2002):** обход снизу вверх,
  контуры поддеревьев через нити (thread), сдвиг поддерева с равномерным распределением по
  промежуточным поддеревьям через shift/change, итоговые координаты через mod. Узлы
  переменной ширины: зазор между соседями `(ширина_левого + ширина_правого)/2 + gap`, где
  gap — `siblingGap` у детей одного родителя и `subtreeGap` иначе.
- **Реализация на индексах и типизированных массивах, без рекурсии:** цепочка из 50 000 узлов
  не переполняет стек (есть тест).
- **Зеркальная симметрия.** Сначала реализация усредняла раскладку дерева и отражённую
  раскладку его зеркала — в предположении, что однопроходный Walker симметрию не гарантирует.
  Проверка до принятия решения: однопроходный вариант на 3 000 случайных деревьях
  (4 525 групп изоморфных поддеревьев) и 50 000 прицельных (корень с 3–7 поддеревьями разной
  глубины, разные зазоры) — ноль нарушений. Усреднение убрано, симметрию охраняет тест на
  300 случайных деревьях.
- **Координаты — левый верхний угол**, уровень занимает высоту самого высокого узла,
  результат нормализован к (0, 0), bounds плотный.
- **Изоляция:** в `tsconfig` пакета `lib: ["ES2023"]` без DOM и `jsx: "preserve"` —
  унаследованный из базы `react-jsx` незаметно подтягивал типы `react/jsx-runtime` в
  программу пакета, где нет ни одного `.tsx`.

### Данные (@entities/org-tree)

- **Схема строгая:** `z.strictObject`, `performance` — `int` 0–100, `updatedAt` —
  `z.iso.datetime()` (проверено: отклоняет 30 февраля и 29 февраля невисокосного года,
  `z.number()` отклоняет `Infinity`/`NaN`). Сверх перечисленного — целостность дерева в
  `superRefine`: уникальные id, `parentId` на существующий узел, отсутствие циклов (O(n)).
  Любое нарушение — `OrgTreeContractError` на весь ответ.
- **`isEqual` — `isSameOrgTree`: равные длины и тот же `updatedAt` у узла с тем же id.**
  ТЗ шага говорило «по максимальному `updatedAt`», это противоречило требованию из ревью
  (удаление узла). Пользователь выбрал `id → updatedAt` из трёх вариантов.
- **fetch:** `fetch('/api/org-tree', { signal })`; `TypeError` → `OrgTreeNetworkError`, не-2xx
  → `OrgTreeHttpError`, `AbortError` пробрасывается как есть (его разбирает `@shared/query`).
  ETag/304 обрабатывает HTTP-кеш браузера.
- **Опроса нет.** Фраза ТЗ шага «индикатор появляется каждые 5 секунд» противоречила
  `@shared/query` без polling; источник истины говорит только «stale time 5 секунд». Ревалидация
  — при повторной подписке после staleTime и по «Повторить».
- **Селекторы на `createSelector`:** индекс `parentId → дети`, корни, id первого уровня,
  раскрываемые id, `selectVisibleTree(state, expandedIds)`. Дети сортируются по имени: сервер
  порядок не гарантирует, а раскладка должна быть стабильной. Сравнение строк, а не
  `Intl.Collator` — инициализация коллатора стоила ~40 мс первой загрузки при CPU 4x;
  следствие — «ё» после «я».
- **Видимое дерево без `size`**, в данных узла — сам `OrgNode` (стабильная ссылка при равных
  данных) и `childCount` (число детей в данных, для шеврона).
- **Агрегаты** — `aggregateSubtrees(nodes)`: суммы headcount и budget, performance, взвешенный
  по headcount, `null` при нулевом суммарном headcount; O(n), без Redux.
- **RootState приложения пакет не знает:** селекторы типизированы корнем
  `{ orgTree: QueryState<OrgNode[]> }`.

### Рендер (@widgets/org-tree)

> Пересмотрено: `2026-09-15-step-01-widget-to-entity.md` — пакет перенесён в `@entities/org-tree`
> (`OrgTreeWidget` → `OrgTreeView`, `OrgNode` → `OrgNodeCard`).

- **Раскрытие — `Set<string>` в `useReducer` виджета, в Redux не попадает.** Состояние
  `null` = «пользователь не трогал», тогда действует набор по умолчанию: раскрыты узлы первого
  уровня, видны дивизионы и отделы. Если таблице на шаге 02 понадобится связь с деревом,
  состояние поднимется в общего родителя или React-контекст, но не в стор (записано в
  `docs/requirements/step-02-table.md`). Следствие: при уходе со страницы раскрытие сбрасывается.
- **Лес из пяти корней.** `layoutTree` принимает одно дерево: `useTreeLayout` оборачивает лес
  в виртуальный корень нулевого размера и после раскладки удаляет его, его рёбра и пустой
  уровень.
  > Исправлено 2026-09-15: корней может быть сколько угодно — «пять» относится только к данным
  > мока, в коде число не зашито. Раскладка вынесена в `layoutForest` и проверена на 0–40
  > корнях (`2026-09-15-step-01-feedback-roots-fsd.md`).
- **`TreeCanvas` знает только `LayoutResult`**, узел рисует `renderNode`. Позицию задаёт
  обёртка `<g transform="translate(x y)">`, в `OrgNode` координаты не приходят — поэтому при
  сдвиге узла `React.memo` его не перерисовывает.
- **Холст не прыгает при раскрытии.** Виджет передаёт `anchorId` — узел, по которому кликнули.
  В `useLayoutEffect` холст сравнивает позицию якоря в старой и новой раскладке и сдвигает
  панораму на разницу × масштаб; коррекция попадает в тот же кадр. Для «Развернуть/Свернуть
  всё» якорь — первый корень.
- **`viewBox` по bounds — только начальная подгонка.** Если `viewBox` всё время следует за
  bounds, при раскрытии меняется масштаб всего дерева, и сдвигом панорамы это не
  компенсировать. Подгонка: масштаб по bounds в пределах 0.75–1 (мельче текст не читается),
  широкое дерево начинается слева.
- **Панорама и зум без состояния React во время жеста:** значение пишется в `transform` группы
  из `requestAnimationFrame` (один кадр — одна запись), в состояние коммитится по `pointerup`
  или через 150 мс тишины после колеса. `wheel` — `{ passive: false }` (нужен
  `preventDefault`), `pointer*` — `{ passive: true }`. Перетаскивание начинается после 4 px;
  отпускание после перетаскивания не считается кликом по шеврону.
- **Зум колесом вокруг центра узла под курсором**, над пустым местом — вокруг центра холста.
  Точка под курсором относительно холста потребовала бы `getBoundingClientRect`; мировые
  координаты узла известны из раскладки.
- **Размер холста — `ResizeObserver`**, без чтения геометрии из DOM.
- **Один делегированный обработчик клика** по `data-chevron`/`data-id`; Alt+клик раскрывает
  ветку рекурсивно (`collectExpandableSubtreeIds`); клик по остальной части узла свободен.
- **Цвет performance — пять статических правил по `data-performance`** в одном классе
  (CSS-переменная `--performance-color`), рядом с индикатором — число. Шеврон — два символа
  (▸/▾), а не поворот: трансформации внутри `foreignObject` WebKit рисует с ошибками.
- **Клавиатурная навигация исключена по указанию пользователя** посреди работы («достаточно
  мыши»): убраны стрелки, Home/End, roving tabindex, доскролл к узлу в фокусе. Роли
  `tree`/`treeitem` тоже убраны — они обещают экранному диктору навигацию стрелками.
  Шеврон — обычная кнопка с `aria-expanded` и `aria-label`.
- **Состояния в одной рамке фиксированной высоты** (`theme.tree.canvasHeight`): скелетон,
  ошибка с «Повторить», пустой ответ, дерево. Индикатор ревалидации и баннер ошибки при
  имеющихся данных — `position: absolute` поверх холста, в поток не влияют. Кнопки тулбара
  видны во всех состояниях (`disabled` без дерева).

### Критический путь рендеринга

- **SVG-атрибуты геометрии (`x`, `y`, `width`, `height`, `transform`, `d`) — не CSS.**
  Это единственные «инлайн» значения; всё остальное — классы styled-components.
- **Правила линтера закрепляют требования** в `packages/**` и `apps/web/src/**`:
  `react/forbid-dom-props` и `react/forbid-component-props` для `style`; `styled`/`css`/
  `keyframes`/`createGlobalStyle` внутри функции; запись в `el.style`, `style.setProperty`,
  `setAttribute('style')`; чтение `getBoundingClientRect`, `offset*`, `client*`, `scroll*`,
  `getComputedStyle`.
- **`eslint-plugin-react` 7.37.5 не объявляет поддержку ESLint 10** (peer `^9.7`): установлен
  через `overrides` в корневом `package.json` и подключён через `fixupPluginRules`.
- **Первая отрисовка не ждёт данных:** оболочка и скелетон рисуются сразу. Стор и роутер
  раньше создавались при импорте модулей — теперь ленивые синглтоны (`getStore`,
  `getRouter`) при первом рендере; не `useState`, потому что StrictMode в dev дважды вызывает
  инициализатор и запустил бы сагу дважды. Первый `root.render` — в `startTransition`, React
  рендерит квантами.
  > Пересмотрено: `2026-09-15-step-01-strict-mode-off.md` — приложение работает без StrictMode.
- **Панорама: transform на `<g>` против `viewBox`.** Замер ниже; разница в пределах шума,
  оставлен `transform` на `<g>`. CSS transform на HTML-обёртке дешевле в 5–6 раз по работе
  главного потока, но это инлайн-стиль, запрещённый источником истины; замерен как эталон.

## Отступления от инструкции

- `isEqual` — `id → updatedAt`, а не максимум `updatedAt` (решение пользователя).
- Периодического опроса нет: «каждые 5 секунд» трактовано как stale time (источник истины).
- Клавиатурная навигация и ARIA-роли дерева не делались (указание пользователя).
- Добавлены `@pages/about`, навигация, `PORT`/`MOCK_API_URL`, дев-ручки из `Referer`.
- Панорама пишет SVG-атрибут `transform`; CSS-вариант не взят из-за «никакого inline-CSS».
- `viewBox` по bounds — только начальная подгонка; зум вокруг узла под курсором, а не точки
  курсора.
- Схема проверяет целостность дерева сверх перечисленных полей.
- Профилирование — через DevTools Protocol в headless Chrome, а не интерфейс DevTools;
  React Profiler заменён временным счётчиком рендеров `OrgNode`.

## Известные проблемы

- Первая загрузка при CPU 4x: одна задача ~110 мс (см. выше).
- Тест `useQuerySubscription` не написан: jsdom не пришёл, клавиатурная навигация исключена.
- Раскрытие сбрасывается при уходе со страницы — состояние намеренно локальное.
- Сортировка по имени без `Intl.Collator`: «ё» после «я».
- Текст ошибок zod в сообщении контракта — на английском (`z.prettifyError`).
- Счётчик подписчиков в `@shared/query` обнуляется при перезапуске саги под `supervise`.
