# Шаг 04, часть 1 — AI-поиск: сервер парсит фразу

Дата: 2026-09-16

> Пересмотрено: 2026-09-16-step-04-ai-search-client.md

Реализован POST /api/search/parse: разбор фразы на естественном языке в структурированный фильтр.
Без `LLM_API_KEY` работает заглушка (словарь из 10 фраз); с ключом — GLM 4.7 FlashX через Timeweb API.

## Решения

**Заглушка через словарь, а не правила** → ТЗ требует 8–12 фраз, покрывающих все поля. Словарь из 10 фраз:
каждая фраза — одно поле или комбинация (уровень + численность). Сопоставление по `includes` в
нормализованном тексте (lowercase, схлопнутые пробелы). Порядок проверки: более длинные фразы первыми
(сортировка по длине ключа), чтобы "большие команды" сработала раньше "команды".

**Zod strictObject, а не object** → ТЗ требует "только известные поля (лишнее — отказ)". `z.strictObject`
отклоняет лишние поля на этапе парсинга, не требуя ручной проверки. Это также даёт мутацию "лишние поля
игнорируются" — замена на `z.object` пропускает лишнее поле, тест "лишнее поле — null" падает.

**Таймаут через AbortController** → ТЗ требует таймаут 5 секунд. AbortController передаётся в
`openai.chat.completions.create` через `options.signal`. При таймауте промис реджектится, catch
возвращает null. Это даёт мутацию "таймаут не срабатывает" — замена `controller.abort()` на `()`
не прерывает запрос, тест "таймаут — null" падает.

**Кэш по нормализованному тексту** → ТЗ требует "одна и та же фраза разбирается одинаково". Map с
ключом `normalize(text)` (lowercase, схлопнутые пробелы). Вытеснение не нужно (53 узла + тестовое
задание). Это даёт тест "кэш: одинаковые фразы — один вызов" — три вызова с разными регистрами
делают один запрос к модели.

**explanation собирается кодом, а не берётся из модели** → ТЗ требует "Собирается из filter кодом,
а не берётся из ответа модели". `buildExplanation` генерирует фразу по-русски из полей filter
(уровни → "команды/отделы/группы", диапазоны → "от N до M", q → "название содержит «X»"). Это даёт
мутацию "explanation из ответа модели" — замена на фиксированную строку ломает тест, проверяющий
конкретную фразу "команды, численность от 20".

**Данные узлов не уходят в модель** → ТЗ требует "Данные оргструктуры в запрос к модели не попадают".
Системное сообщение содержит только инструкцию и примеры формата, пользовательское сообщение — только
текст запроса. Тест "в аргументах вызова модели нет данных узлов" проверяет что system content не
содержит "node-" или "uuid-". Это даёт мутацию "данные узлов уходят в модель" — добавление
`process.env.NODES` в user content ломает тест.

**Fallback на text при пустом apiKey** → ТЗ требует "ключ пуст — работает заглушка". Проверка
`if (!apiKey)` вызывает `parseStub`, не создавая OpenAI-клиент. Это даёт мутацию "при пустом ключе
всё равно идёт вызов" — добавление `&& false` заставляет идти в LLM, тесты заглушки падают.

**Обработка ошибок: любая → null** → ТЗ требует "Любая ошибка → null и запись в лог. Наружу ошибка
не выходит". Try-catch вокруг всего LLM-вызова (JSON.parse, zod.parse, validateFilter). Любое
исключение логируется и возвращает null. Это даёт мутацию "сбой модели выходит как 500" — замена
`return null` на `throw error` ломает тесты "невалидный JSON — null" и другие.
