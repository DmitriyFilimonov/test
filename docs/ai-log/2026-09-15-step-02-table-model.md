# Шаг 02, часть 1 — модель аналитической таблицы

> Пересмотрено: 2026-09-15-step-02-grouped-table.md

Дата: 2026-09-15

В `@entities/org-tree` добавлена модель таблицы: селектор строк `selectTableRows` поверх
существующего расчёта итогов, форматтеры бюджета и эффективности, флаг `matches` у узлов
видимого дерева. UI не менялся, `aggregate.ts` не менялся.

## Изменения

- `@entities/org-tree`:
  - новый `model/table.ts` — `selectTableRows(state, params)`, тип `TableRow`;
  - новый `model/format.ts` — `formatBudget`, `formatPerformance`, константы
    `BUDGET_GROUP_SEPARATOR`, `BUDGET_SUFFIX`, `EMPTY_VALUE`;
  - `model/selectors.ts` — новый `selectNodeLevels`, поле `matches` в `OrgTreeItem`, комментарий
    к `selectSubtreeAggregates`;
  - `index.ts` — экспорт нового;
  - тесты: новые `model/table.test.ts` (12) и `model/format.test.ts` (13); в
    `lib/nodeMetrics.test.ts` и `lib/useTreeLayout.test.ts` в собранные вручную `OrgTreeItem`
    добавлено поле `matches`.
- `scripts/mutation`: новые наборы `entities-table` (4) и `entities-format` (6), в
  `entities-selectors` +4.
- Документы: `README.md` (модель таблицы, трактовки, качество, таблицы мутаций, ограничение
  про двойной расчёт), `docs/requirements/step-02-table.md`.

## Решения

- **`level` — глубина узла в дереве, считается на клиенте.** В ТЗ «level — из ответа
  сервера», но в контракте части 0 поля `level` у узла нет: оно определено только как колонка
  сортировки. Агент спросил; пользователь ответил, что имеется в виду уровень дерева, и его можно
  вычислить при переходе от списка к дереву. Сделано так: `selectNodeLevels` обходит от корней
  индекс детей `selectChildrenIndex` — ту же структуру, из которой строится дерево.
  Мемоизирован по данным, от раскрытия не зависит.

  Отброшены:
  - `level` в ответе — меняет контракт части 0, схему и мок (вариант из вопроса, не выбран);
  - глубина внутри `aggregateSubtrees` — там уже есть обход от корней, но уровень не итог
    поддерева: пришлось бы менять `SubtreeAggregate` и `aggregate.ts`.

- **Итоги строк — проекция `selectSubtreeAggregates`, своего расчёта нет.** Селектор таблицы
  берёт итоги из того же мемоизированного селектора, что и дерево, поэтому на одну ссылку
  `data` приходится один вызов `aggregateSubtrees` на дерево и таблицу вместе. Итоги считаются
  по всем узлам, а фильтр `matches` применяется к строкам уже после.

  Отброшен вызов `aggregateSubtrees` прямо в `selectTableRows`: реализация была бы одна, но
  расчётов на данные — два, у каждого своя мемоизация. `aggregate.ts` не менялся, поэтому
  мутаций на его новое поведение нет.

- **Порядок — раскладка по `order`, без сортировки.** Узел кладётся в массив длины n на
  позицию `order`, затем несовпавшие пропускаются. Сравнений нет, O(n). Держится на проверке
  схемы из части 0: `order` — перестановка 0..n-1.

  Отброшен `toSorted((a, b) => a.order - b.order)`: результат тот же, но это сортировка на
  клиенте за O(n log n), что расходится с «клиент не пересортировывает».

- **Флаг `matches` в `OrgTreeItem`** дублирует `node.matches`: отдельное поле явно просит ТЗ.

- **`formatBudget`.**
  - Один на модуль `Intl.NumberFormat('ru', { maximumFractionDigits: 0 })` разбивает число на
    части (`formatToParts`); части типа `group` заменяются константой U+00A0.
  - Число всегда в целых рублях.
  - Перед «руб.» тоже неразрывный пробел, чтобы число и единица не разрывались переносом
    (трактовка; в ТЗ суффикс записан как « руб.»).

  Замер в Node 24.21 (ICU 78.3): первое создание форматтера — ~11 мс; создание на каждый вызов
  — ~14 мкс против ~2 мкс с общим форматтером, в 7 раз дороже.

  В Node 24 (ICU 78.3) и в Node 20 (ICU 74.2) разделитель групп для ru — U+00A0, так что
  проверка «разделитель — именно константа» на настоящем ICU пропустила бы мутацию «разделитель
  из Intl как есть». Поэтому отдельный тест подменяет `formatToParts` ответом с U+202F, как в
  версиях ICU с узким пробелом.

- **`formatPerformance` округляет как карточка** (`Math.round`, `null` — «—»). Совпадение
  закреплено тестом, который сравнивает результат с `getMetricRows(getNodeMetrics(…))` для
  каждого узла фикстуры. `nodeMetrics.ts` не переведён на `formatPerformance`: ТЗ запрещает
  трогать UI, а вывод карточки не должен меняться.

- **Счётчик пересчёта — `vi.mock('./aggregate', { spy: true })`.** Реализация настоящая, вызовы
  считаются. Ревалидация с равными данными проверяется на реальном сторе с сагой и подменённым
  `fetch`, а не на собранном вручную стейте. Так проверена вся цепочка: `isEqual` сохраняет
  ссылку на `data`, селекторы итоги не пересчитывают.

- **Устройство мутаций.**
  - «Агрегация зависит от expandedIds» смоделирована переносом расчёта итогов в комбинатор
    `selectVisibleTree`: пересчёт на каждое раскрытие.
  - «Итоги только по совпавшим потомкам» написана через `selectSubtreeAggregates.resultFunc`,
    без новых импортов: мутант должен работать, а не падать с `ReferenceError` и засчитываться
    убитым по посторонней причине.
  - «Свой обход поддерева» — рекурсивная сумма по `parentId` прямо в `selectTableRows`. Её
    ловит счётчик: таблица без дерева обязана вызвать `aggregateSubtrees` ровно один раз.

- **Хуков для таблицы нет** (`useTableRows` и т. п.): ТЗ ограничивает часть чистыми функциями и
  селекторами.

## Отступления от инструкции

- `level` не из ответа сервера (в контракте его нет): это глубина в дереве, по ответу
  пользователя на вопрос агента.
- Суффикс бюджета — U+00A0 + «руб.», а не обычный пробел + «руб.» (трактовка, см. «Решения»).
- Сверх ТЗ:
  - экспортируются `selectNodeLevels`, `BUDGET_SUFFIX`, `EMPTY_VALUE`;
  - тесты: имитация ICU с U+202F, округление бюджета и эффективности, сверка с карточкой, флаг
    `matches` в дереве, пустые данные;
  - 8 мутаций сверх минимума: уровни (2), флаг `matches`, разделитель из Intl, `style: 'currency'`,
    дробные рубли, null как 0, эффективность без округления.

## Известные проблемы

- Эффективность форматируется в двух местах — `formatPerformance` и `getMetricRows` (карточка).
  Совпадение закреплено тестом, общего кода нет.
- Уровень, как и итоги, считается и на клиенте, и в моке для сортировки (ограничение в README).
- В названиях тестов `formatBudget` из `it.each` перед «руб.» печатается обычный пробел, а
  проверяется значение с U+00A0 — это только текст названия.
