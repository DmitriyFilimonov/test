# Шаг 03, часть 1 — SSE-транспорт и индикатор соединения

Дата: 2026-09-15

Проверка реализации шага 03 части 1: сервер рассылает обновления через SSE, клиент получает и показывает состояние соединения. Всё оказалось реализовано, кроме одной ошибки в dom-тесте.

## Изменения

- `packages/pages/org-dashboard/src/OrgDashboardPage.dom.test.tsx` — добавлены `orgTreeLiveSlice` и `orgTreeLiveSaga` в конфигурацию тестового стора, заглушен `EventSource`.

Остальное уже реализовано:

- `apps/mock-api` — SSE на `GET /api/org-tree/stream`, дев-ручки `start`/`stop`/`emit`/`kill`, `touch` рассылает патчи подписчикам.
- `packages/shared/live` — пакет `@shared/live` с сагой, backoff, каналами, полным набором тестов.
- `packages/entities/org-tree` — `orgTreeLive` через `createLiveSource` с zod-разбором событий, хуки подписки и статуса.
- `packages/pages/org-dashboard` — `<LiveIndicator />` в шапке с обратным отсчётом и кнопкой переподключения.
- `scripts/mutation/src/suites/shared-live*.ts` — 3 набора, 15 мутаций.

## Решения

**SSE, а не WebSocket** → поток односторонний (сервер → клиент), идёт поверх HTTP через прокси Vite без отдельного сервера. WebSocket отброшен: двусторонний обмен здесь не нужен, сложнее инфраструктура. Поллинг отброшен: лишние запросы при редких изменениях, задержка реакции зависит от интервала.

**Индикатор в `@pages/org-dashboard`, а не в `@shared/ui`** → индикатор специфичен для страницы дашборда, использует хуки `@entities/org-tree`. В `@shared/ui` ему не место: он зависит от конкретных селекторов и экшенов, а не от абстрактного API.

**Attempt сбрасывается по открытию, а не по первому сообщению** → открытое соединение уже успех, даже если сервер молчит. Сброс по сообщению давал бы ложные неудачи при медленном старте потока.

**Visibilitychange ускоряет повтор** → пользователь вернулся на вкладку, смотрит на страницу сейчас; пауза backoff могла вырасти до потолка, пока вкладка была в фоне. Попытка сразу даёт актуальное состояние без ожидания.
