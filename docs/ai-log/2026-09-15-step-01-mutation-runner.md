# Шаг 01 — мутационная проверка в репозитории

Дата: 2026-09-15

Одноразовые скрипты мутационной проверки из временной папки сессии перенесены в
репозиторий: workspace `scripts/mutation` (`@scripts/mutation`), команда
`npm run test:mutation`. Два набора — `shared-query` (12 мутаций) и `web-supervise` (3),
все 15 убиты. Раннер отдельно проверен на неудачных исходах и на прерываниях.

## Изменения

- `scripts/mutation/` — новый workspace: `src/run.ts` (CLI и оркестрация),
  `src/vitest.ts` (запуск vitest и разбор JSON-отчёта), `src/types.ts`,
  `src/suites/{shared-query,web-supervise,index}.ts`, `README.md`, `package.json`, `tsconfig.json`.
- Корневой `package.json` — `workspaces` += `scripts/*`, скрипт `test:mutation`.
- `.gitignore` — `*.mutation-backup`.
- `eslint.config.js` не менялся: блок `**/*.{ts,tsx}` уже покрывает раннер.
- `CLAUDE.md` — раздел «Мутационная проверка»; `docs/requirements/readme.md` — таблицу
  для README генерировать командой.

## Решения

**Отдельный workspace, а не папка со скриптом.** Так раннер попадает в
`lerna run lint` и `lerna run typecheck` без правок корневых скриптов, как любой пакет
(«в каждом пакете lint и typecheck»). Цена — `scripts/*` в `workspaces`, которые на шаге 01
были заданы явно; это отступление.

**TypeScript без сборки и без tsx.** Node 24 исполняет `.ts` сам
(`process.features.typescript === 'strip'`), база tsconfig уже требует
`erasableSyntaxOnly`. Относительные импорты — с расширением `.ts`
(`allowImportingTsExtensions`), потому что Node их не дописывает. Новых зависимостей нет:
`vitest` и `@types/node` уже были в дереве.

**Мутации — TS-модули, а не JSON.** Многострочные фрагменты кода в JSON превращаются
в строки с `\n`, их трудно ревьюить; в TS-модуле набор типизирован (`Suite`, `Mutation`)
и проверяется `tsc`.

**Разбор JSON-отчёта vitest вместо текста.** Одноразовый скрипт парсил verbose-вывод
регулярным выражением и дважды ошибся (см. `2026-09-15-step-01-review-fixes.md`).
Теперь `--reporter=json --outputFile=<tmp>`: упавшие тесты — `assertionResults[].status`,
ошибки уровня файла — `testResults[].message`.

**Пять статусов, успех — только если все `killed`.** `survived` — дыра в тестах;
`invalid` — фрагмент найден не ровно один раз (код изменился); `timeout`; `error` —
ненулевой код без упавших тестов (например, мутант не парсится). Раньше последние два
случая сливались с «выжила» или «убита».

**Базовый прогон перед мутациями.** Если тесты набора не зелёные без мутаций, любая
мутация выглядела бы убитой. Такой набор пропускается, код выхода 1.

**Безопасность записи в исходник.**

- Замена через функцию: `replace(from, () => to)`, иначе `$&`/`$1` в коде мутации
  интерпретировались бы.
- Отдельная группа процессов (`spawn(..., { detached: true })`) и `process.kill(-pid)`:
  по таймауту убиваются и воркеры vitest. Раньше `execSync` с таймаутом убивал только
  главный процесс, и воркер оставался висеть.
- Восстановление файла после каждой мутации, в `finally` набора, по SIGINT/SIGTERM/SIGHUP и
  на `exit`; после набора — сверка содержимого с исходным.
- Копия `<файл>.mutation-backup` на диске на время набора — на случай `kill -9`. Если
  копия найдена при запуске, раннер отказывается работать, пока файл не восстановлен.

**`--markdown`.** Таблицы для журнала и README генерируются из прогона, а не
собираются руками.

## Отступления от инструкции

- В `workspaces` добавлен `scripts/*` (причина выше).

## Проверки

`npm run test:mutation` — exit 0:

```
▶ shared-query — packages/shared/query/src/createQuery.ts (12 мутаций)
  базовый прогон: 12 тестов, все зелёные [0.3 с]
  KILLED × 12
▶ web-supervise — apps/web/src/app/store/supervise.ts (3 мутации)
  базовый прогон: 4 теста, все зелёные [0.3 с]
  KILLED × 3
Итого: 15 мутаций — killed 15, survived 0, invalid 0, timeout 0, error 0
```

Весь прогон ≈ 6 с (≈ 0,3 с на мутацию). Какие тесты убивают какие мутации — совпадает
с таблицами в `2026-09-15-step-01-review-fixes.md`. Целевые файлы после прогона побайтово
совпадают с копиями, сделанными до него.

Проверка самого раннера — временные пробные наборы (удалены):

| Проба                                        | Ожидание                  | Результат                                                          |
| -------------------------------------------- | ------------------------- | ------------------------------------------------------------------ |
| правка комментария в `supervise.ts`          | survived                  | `SURVIVED`                                                         |
| фрагмента нет в файле                        | invalid                   | `INVALID … найден 0 раз(а)`                                        |
| фрагмент `yield*` (2 вхождения)              | invalid                   | `INVALID … найден 2 раз(а)`                                        |
| мутант уходит в синхронный цикл, таймаут 8 с | timeout                   | `TIMEOUT [8.0 с]`, зависших процессов vitest нет                   |
| `export function** supervise`                | error                     | `ERROR` + `[PARSE_ERROR] Expected ( but found **` с номером строки |
| набор с намеренно падающим тестом            | базовый прогон не зелёный | мутации не запускались, упавший тест назван                        |

Итог пробного прогона: exit 1, файл восстановлен, копии нет.

Прерывания (набор `shared-query`, сигнал после того, как мутация записана в файл):

- **SIGINT** — `Прервано (SIGINT). Изменённый файл восстановлен.`, exit 130; файл равен
  оригиналу, копии нет, vitest не остался.
- **`kill -9`** — обработчики не срабатывают: файл остался с мутацией (`data,`), копия на
  месте; осиротевший vitest завершился сам. Повторный запуск — отказ с путём к копии,
  exit 1, файл не тронут. `mv <копия> <файл>` — файл побайтово равен оригиналу.

Найдено и исправлено по ходу проверки: для `error` раннер показывал только строку
«JSON report written to …» — теперь выводится `testResults[].message` без ANSI-кодов;
склонения в выводе («4 тестов», «3 мутаций»).

`npx vitest run` — 16/16. `npx lerna run typecheck --no-bail && npx lerna run lint --no-bail` —
8/8 и 8/8 (новый `@scripts/mutation`), exit 0. `npm run build -w @app/web` — успешно.
`prettier --check .` — чисто.

## Известные проблемы

- Мутации пишутся в рабочие файлы: во время прогона нельзя редактировать целевые файлы,
  а открытый dev-сервер Vite покажет мутанта через HMR (описано в README раннера).
- Мутации придуманы вручную: раннер проверяет только описанные регрессии. Автогенерация
  (Stryker) не подключалась.
- Тесты раннера — ручные пробы из этой записи, автотестов у самого раннера нет.

  workspace, TS через встроенную поддержку Node, JSON-отчёт vitest, статусы
  `invalid`/`timeout`/`error`, базовый прогон, копия на диске и отказ при её наличии.
