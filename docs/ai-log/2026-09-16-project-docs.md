# Документация проекта: архитектура, модель данных, ADR, скриншоты

Дата: 2026-09-16

Проверка проекта на требования к документации и их выполнение: добавлены `docs/architecture.md`,
`docs/data-model.md`, девять ADR в `docs/adr/`, скриншоты. В README — запуск одной командой в
начале, раздел «AI в разработке», ссылки на документацию и unit-тесты агрегации.

## Изменения

- `docs/architecture.md` — части системы, слои FSD, где живёт состояние, поток данных от API до

- `docs/data-model.md` — узел и дерево, алгоритм агрегации (полный и инкрементальный), контракт

- `docs/adr/README.md` и `001`–`009`.
- `docs/screenshots/` — `split.png`, `ai-search.png`, `tree.png`.
- `README.md`:
  - «Запуск» начинается с `docker compose up --build`;
  - новые разделы «Скриншоты» и «Документация»;
  - пункт про unit-тесты агрегации в «Качестве»;
  - «Работа с AI» переписан в «AI в разработке»;
  - одно предложение во вступлении о живых обновлениях и AI-поиске.

## Решения

**Что было и чего не было** → запуск одной командой был (`docker compose up --build`), но во втором
разделе после двух команд локального запуска — перенесён в начало «Запуска». Unit-тесты функции
агрегации были (`aggregate.test.ts`, `aggregate.patch.test.ts`), README на них не указывал. Раздел
про AI был под другим названием и без шагов 03–04. Скриншотов, `architecture.md`, `data-model.md`
и `adr/` не было.

**Скриншоты с запущенного Docker-стека через headless Chrome и CDP** → финальный результат — это
production-сборка за nginx. Скрипт на встроенном в Node 24 `WebSocket`, без зависимостей, вне
репозитория. Три кадра: split с выбранной строкой и подсветкой патча (перед снимком —
`POST /api/dev/stream/emit`), таблица со структурным фильтром после настоящего разбора фразы
моделью, дерево после «Развернуть всё» с уменьшенным колесом масштабом. Кадры просмотрены; дерево
переснималось несколько раз — то видно три карточки, то всё слишком мелко или обрезано.

**ADR — по журналу, с пометкой, где альтернатив не было** → ADR пишутся после реализации: контекст
и отброшенные варианты взяты из секций «Решения» записей журнала. Где журнал альтернативу не
рассматривал (RTK Query и TanStack Query, готовые библиотеки раскладки, Stryker), это сказано
прямо, а не достроено задним числом. Решения, заданные ТЗ, помечены как решения автора.

**Отбор ADR** → нетривиальные решения, у которых есть реальные альтернативы и последствия для
следующего кода: структура пакетов, кеш на redux-saga, транспорт SSE, патчи в кеш, инкрементальные
агрегаты, URL как источник правды, раскладка и холст, AI-поиск, мутационная проверка. Не взяты:
один бандл без разделения кода (запрет задания, а не решение), настройки nginx (описаны в README
«Сборка и выкладка»).

**Раздел «AI в разработке» — списками, а не таблицей** → в прежней таблице одна ячейка решений
человека занимала сотни символов в строке. Решения сгруппированы по шагам, добавлены решения
шагов 03–04 из секций «Авторство», добавлены инструменты (ответ автора) и то, как проверялся
результат агента.

**Контракт патча — независимо от транспорта** → содержимое `hello` и `patch` описано отдельно от
SSE-кадров, с явной оговоркой в начале раздела; обоснование SSE — ADR-003.

## Отступления от инструкции

- **«Контракт WebSocket-патча»** — в проекте транспорт SSE (решение шага 03). Описан контракт
  фактического потока с оговоркой, что содержимое событий от транспорта не зависит; транспорт не
  менялся.
- **Скриншоты, а не GIF** — требование допускает любое; `ffmpeg` и других средств сборки GIF на
  машине нет.
- **Прочитаны записи журнала прошлых шагов**, хотя `CLAUDE.md` это запрещает без прямой ссылки в
  задаче: ADR требуют контекста и альтернатив, а раздел про AI по плану `docs/requirements/readme.md`
  собирается из секций «Авторство». Читались только секции «Решения» и «Авторство» нужных записей и
  поиск по ключевым словам, не записи целиком.
- **Скриншот AI-поиска вызвал модель** — фраза «команды численностью больше 10» ушла в Timeweb AI
  с ключом из `.env` автора через запущенный стек. Данных оргструктуры в запросе нет.
- **Данные на скриншотах отличаются от стартовых** — в стеке работала автогенерация патчей.
- **Пункты `docs/requirements/readme.md` не отмечены `[x]`** — план отмечается при финальном сведении
  README после подтверждения автора, а этого подтверждения не было.

## Известные проблемы

- Скрипт скриншотов не в репозитории: при изменении UI кадры придётся снимать заново вручную.
- `CLAUDE.md` не требует обновлять `architecture.md`, `data-model.md` и заводить ADR — документы
  могут разойтись с кодом на следующих шагах.
