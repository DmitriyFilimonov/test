# ADR-009: Мутационная проверка тестов описанными регрессиями

- Статус: принято
- Дата: 2026-09-15
- Источник: `docs/ai-log/2026-09-15-step-01-mutation-runner.md`,
  `2026-09-15-step-01-shared-query.md`, `2026-09-15-step-01-review-fixes.md`

## Контекст

Код и тесты пишет AI-агент. Зелёные тесты и покрытие не показывают, ловят ли тесты регрессии:
тест может выполнять строку и ничего о ней не утверждать. На шаге 01 проверка «сломать код —
тест должен упасть» делалась одноразовым скриптом, и его разбор текстового вывода vitest дважды
ошибся. Автор решил держать мутационные скрипты в репозитории.

## Решение

- **Пакет `@scripts/mutation`** — раннер и наборы мутаций в TypeScript (`scripts/mutation/src/suites/`).
- **Мутация — описанная регрессия:** файл, фрагмент `from` → `to`, человекочитаемое имя
  («среднее не взвешено по headcount»). Набор — мутации одного файла.
- **Раннер** подменяет фрагмент, гоняет тесты с JSON-отчётом vitest и восстанавливает файл.
  Статусы: `killed` (тест упал — хорошо), `survived` (дыра в тестах), `invalid` (фрагмент не найден
  ровно один раз — код изменился), `timeout`, `error`. Успех — только если все `killed`.
- **Базовый прогон** перед мутациями: если тесты набора красные без мутаций, набор пропускается.
- **Безопасность исходников:** восстановление после каждой мутации, по сигналам и на выходе,
  копия файла на диске на время набора; найденная копия блокирует запуск.
- **Таблицы «что сломали → что упало»** в README генерируются `--markdown`, не пишутся руками.
- **Правила в `CLAUDE.md`:** новый тест на требование — новая мутация; `survived` — дописать тест,
  удалять мутацию нельзя; фрагменты устойчивы к Prettier.

## Альтернативы

- **Только покрытие.** Показывает выполненные строки, а не проверенные утверждения.
- **Автоматическая генерация мутантов (Stryker).** Не подключалась; в журнале это записано как
  ограничение: раннер проверяет только описанные регрессии. Ручные мутации называют требование,
  которое ломают, и таблица читается как список гарантий тестов.
- **Одноразовые скрипты в сессии агента.** Не воспроизводятся читателем и уже ошибались в разборе
  вывода.

## Последствия

- 285 мутаций в 55 наборах, все `killed`; результат воспроизводится `npm run test:mutation`.
- Полный прогон дорогой — весь набор тестов на каждую мутацию. Во время работы гоняются наборы
  изменённых файлов, полный — один раз в конце задачи; параллельно с другими процессами не
  запускается.
- Правка кода делает мутации `invalid` — фрагменты приходится переякорять; поэтому форматирование
  выполняется до мутаций, а не после.
- Мутации, которые никто не описал, не проверяются.
