# ADR-008: AI-поиск — модель переводит фразу в фильтр, фильтрует клиент

- Статус: принято
- Дата: 2026-09-16
- Источник: `docs/ai-log/2026-09-16-step-04-search-parse.md`,
  `2026-09-16-step-04-ai-search-client.md`, `2026-09-16-step-04-docker.md`

## Контекст

Шаг 04: вместо формы с восемью полями фильтра пользователь пишет фразу — «команды численностью
больше 10», «отделы с бюджетом от 500 тысяч». Все 53 узла с итогами уже в памяти клиента, данные
обновляются патчами. Ключ языковой модели нельзя отдавать в браузер. Провайдер — Timeweb AI,
модель GLM 4.7 FlashX (выбор автора).

## Решение

- **Сервер переводит фразу в фильтр:** `POST /api/search/parse { query }` →
  `{ mode: 'structured' | 'text', filter, explanation }`. В модель уходят только постоянная
  инструкция с примерами формата и текст пользователя; данных оргструктуры в запросе нет.
- **Ответ модели не доверенный:** срезается markdown-ограждение, `JSON.parse`, строгая zod-схема
  (лишние поля — отказ, числа целые, `levels` — 1–3, эффективность 0–100, min ≤ max). Пустой
  фильтр, сбой сети, лимит, таймаут 30 с — `mode: 'text'`, работает обычный поиск по названию.
- **Кэш удачных разборов** на сервере по нормализованному тексту (регистр, пробелы). Разбор
  зависит только от фразы, не от данных; сбой не кэшируется.
- **Фильтрует клиент:** `applyStructuredFilter` поверх строк таблицы из стора, предки совпавших
  строк — строками контекста. Фильтр не входит в параметры запроса и в ключ кеша.
- **Фильтр — в адресе** (`levels`, `minHeadcount`, …), `q` при этом очищается; плашка над таблицей
  показывает условия с возможностью снять каждое или вернуться к поиску по тексту.
- **Текст ищется сразу:** через 250 мс после ввода фраза уходит в `q`, разбор идёт параллельно и
  отменяется новой правкой.
- **Без ключа модели нет:** заглушки-словаря нет (решение автора: «нет LLM — нет LLM»).

## Альтернативы

- **Отдать модели данные и попросить выбрать узлы.** Данные уходят внешнему провайдеру, стоимость
  растёт с размером дерева, результат недетерминирован и устаревает с первым патчем.
- **Вызывать модель из браузера.** Ключ оказался бы в бандле.
- **Фильтровать на сервере параметрами запроса.** Новый ключ кеша и запрос на каждый фильтр, хотя
  все данные уже на клиенте.
- **Словарь-заглушка без ключа.** Отклонено автором: «нет LLM — нет LLM».
- **Stale-while-revalidate для разбора.** Реализовывалось и откачено по решению автора.

## Последствия

- Результат фильтра следует за живыми данными: команда, чья численность изменилась патчем,
  появляется в таблице или пропадает без нового разбора. Кэш разбора от патчей не устаревает.
- Ссылка с фильтром открывается без вызова модели.
- Разбор занимает секунды; до ответа таблица показывает текстовый результат.
- Без `LLM_API_KEY` любая фраза — текстовый поиск. Ключ передаётся только сервису `api`, в образы и
  сборку клиента не попадает.
- Кэш — `Map` без ограничения размера, живёт до перезапуска сервера: для мока приемлемо.
