# ADR-004: Патч — в текущий ключ кеша, остальные ключи протухают

- Статус: принято
- Дата: 2026-09-16
- Источник: `docs/ai-log/2026-09-16-step-03-live-apply.md`

## Контекст

Кеш хранит ответы по ключам параметров `q`, `sort`, `dir` ([ADR-002](002-query-cache-on-redux-saga.md)).
Узлы в них одни и те же, но `matches` (совпадение с `q`) и `order` (позиция в серверной
сортировке) у каждого ключа свои, и считает их сервер: сортировка по имени — локалью ru, по
итогам — суммами поддерева. Патч потока несёт новые значения метрик, добавленные и удалённые узлы
— без `matches` и `order`. Патчи приходят раз в несколько секунд, пользователь в это время
смотрит на таблицу и дерево и может держать курсор на строке.

Основные правила заданы ТЗ шага 03 (часть 3); реализация и трактовки — агента.

## Решение

- **Патч применяется только к записи текущего ключа** — последнего, на который подписался UI, —
  экшеном `patched(params, updater)`: данные меняются без запроса, `fetchedAt` — время патча.
- **Остальные ключи помечаются протухшими** `invalidated(predicate)`: `fetchedAt` сбрасывается,
  данные остаются. При возврате к ключу — перезапрос, до ответа видны прежние данные.
- **`order` и `matches` не пересчитываются.** Изменённый узел остаётся на своей позиции, даже если
  по новому значению сортировка поставила бы его иначе. Удаление сдвигает `order` следующих,
  добавленный узел встаёт последним; `matches` добавленного — `true` при пустом `q`, иначе `false`
  до ответа сервера.
- **Перезапрос — только при пропуске:** `seq` больше ожидаемого или `hello` после переподключения
  с другим номером. Повтор уже учтённого `seq` игнорируется.
- **Подсветка без таймеров.** Для изменённых показанных значений в стор пишется номер патча;
  элемент получает `data-updated`, CSS-анимация гаснет сама. Состояния «подсвечено» нет.

## Альтернативы

- **Перезапрос на каждый патч.** Сеть на каждое изменение, задержка на время ответа; патч
  превращается в сигнал «данные устарели».
- **Патчить все ключи, пересчитывая `matches` и `order` на клиенте.** Дублирует серверную
  сортировку и поиск; порядок по имени уже расходится между сравнением строк на клиенте и локалью
  ru на сервере.
- **Пересортировать текущий ключ после патча.** Строки прыгали бы под курсором каждые несколько
  секунд.
- **Состояние «подсвечено» с таймерами снятия.** Лишние рендеры на снятие, таймеры нужно чистить
  при размонтировании и повторном обновлении.

## Последствия

- Живые значения видны без сетевых запросов; перерисовываются только строка, карточка узла и
  карточки предков.
- Порядок строк после патча может не совпадать с тем, что вернул бы сервер, — до следующего
  запроса этого ключа.
- Возврат к другим параметрам после патчей — всегда запрос.
- Ответ GET не содержит `seq`: патчи между сборкой ответа и первым `hello` не видны как пропуск,
  а ответ, собранный раньше патча, перезаписывает его значения до следующего патча.
- Патч, пришедший, пока у текущего ключа ещё нет своих данных, не применяется — данные придут
  ответом.
