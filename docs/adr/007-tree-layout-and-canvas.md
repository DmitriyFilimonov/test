# ADR-007: Своя раскладка tidy tree, SVG-холст, панорама и зум мимо React

- Статус: принято
- Дата: 2026-09-15
- Источник: `docs/ai-log/2026-09-15-step-01-tree-render.md`,
  `2026-09-15-step-01-feedback-roots-fsd.md`, `2026-09-15-step-03-keyboard-animation.md`

## Контекст

Интерактивное оргдерево: карточки подразделений с четырьмя метриками, раскрытие и скрытие
ветвей, панорама и зум, анимация раскрытия. Ограничения — критический путь рендеринга: без
инлайн-CSS (требование задания), без чтения геометрии из DOM, без лишних перерисовок. Замеры —
в production-сборке при замедлении CPU в 4 раза.

## Решение

- **Раскладка — `@shared/tidy-tree`:** Reingold–Tilford с улучшениями Walker в линейной версии
  Buchheim–Jünger–Leipert, узлы переменной ширины. Только числа: без DOM и React, на индексах и
  типизированных массивах, без рекурсии. Лес — через виртуальный корень.
- **Размеры узлов — константы темы.** Раскладка не ждёт измерения карточек.
- **Холст — SVG:** рёбра — `path`, карточки — HTML в `foreignObject`. `TreeCanvas` знает только
  результат раскладки; позицию узла задаёт обёртка `<g transform>`, поэтому сдвиг не перерисовывает
  карточку (`React.memo`, примитивные пропсы).
- **Панорама и зум — мимо состояния React.** Во время жеста `transform` группы пишется из
  `requestAnimationFrame` (один кадр — одна запись), в состояние — один раз в конце жеста. Зум
  колесом — вокруг центра узла под курсором: его мировые координаты известны из раскладки.
- **Холст не прыгает при раскрытии:** сдвиг узла, по которому кликнули, компенсируется панорамой в
  том же кадре (`useLayoutEffect`).
- **Анимация раскрытия** — `opacity` и `transform` появляющихся и исчезающих узлов; позиции
  покадрово не пересчитываются. При `prefers-reduced-motion` — мгновенно.

## Альтернативы

- **Однопроходный Walker против усреднения с зеркалом.** Сначала раскладка усреднялась с
  отражённой, в предположении, что однопроходный алгоритм не гарантирует симметрию. Проверка на
  3 000 случайных и 50 000 прицельных деревьях — ноль нарушений; усреднение убрано, симметрию
  охраняет тест.
- **Способ панорамы — замер:** `transform` на `<g>` и `viewBox` на `<svg>` — ~1.1–1.8 мс главного
  потока на кадр (разница в шуме); CSS `transform` на HTML-обёртке — ~0.2 мс за счёт композитинга,
  но это инлайн-стиль, запрещённый заданием.
- **Панорама через состояние React.** Рендер дерева на каждое движение указателя.
- **`viewBox`, следующий за границами дерева.** При раскрытии менялся бы масштаб всего дерева,
  сдвигом панорамы это не компенсировать; подгонка по границам — только начальная.
- **Готовые библиотеки раскладки и рендера графов** в журнале не рассматривались.

## Последствия

- Раскладка линейна: ~0.4–0.9 мс на 1000 узлов при 10 000 и 100 000; инварианты (нет пересечений,
  родитель по центру, изоморфные поддеревья одной формы, зеркальность) проверяются на 300
  случайных деревьях.
- Панорама 3 с при CPU 4x — 82 движения, 82 кадра, задач длиннее 50 мс нет; раскрытие узла
  перерисовывает 4 карточки из 22.
- Панорама и зум — исключение из правила «состояние компонента в хуке модели»; переделка требует
  повторных замеров (записано в `CLAUDE.md`).
- `foreignObject` в Safari не проверялся; внутри него не используются трансформации (WebKit рисует
  их с ошибками) — шеврон сменой символа, а не поворотом.
- Клавиатурная навигация по дереву стрелками исключена автором; у карточки — кнопки выбора и
  раскрытия, поэтому путь Tab по дереву длинный.
